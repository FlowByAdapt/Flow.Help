# Opening Views

Openings Manager includes a set of tools for creating, repairing,
dimensioning and placing opening elevations.

The workflows differ for windows, doors and curtain walls, so use this
page as the starting point for opening-view documentation.

------------------------------------------------------------------------

## Recommended Workflow

A typical opening-view workflow is:

1.  Review opening marks.
2.  Standardise or renumber openings where required.
3.  Generate window and door views.
4.  Generate curtain wall views separately.
5.  Conform existing opening views where required.
6.  Dimension window views.
7.  Place opening views on sheets.
8.  Refresh Openings Manager and review the final status.

!!! tip "Resolve marks first"

    Opening marks are used by the view-generation and view-audit workflows.

    Resolve non-standard or incorrect marks before generating the opening views.

------------------------------------------------------------------------

## Window Views

Window elevations are generated for **New** windows.

The generated view name is based on the window **Mark**.

For example:

``` text
W01
W02
W03
```

Flow also attempts to add the standard window schedule tag when the view
is created.

➡️ [**Generating Opening Views**](generating-opening-views.md)

------------------------------------------------------------------------

## Door Views

Door elevations are generated for **New** doors.

Unlike window elevations, Flow creates **one door view per door type**,
rather than one view for every door instance.

Door view names are based on the door type's **Type Mark** and use the
`-D` suffix.

For example:

``` text
01-D
02-D
```

Flow also attempts to add the standard door schedule tag.

➡️ [**Generating Opening Views**](generating-opening-views.md)

------------------------------------------------------------------------

## Curtain Wall Views

Curtain wall elevations use a separate interactive workflow.

You select each curtain wall from the model and indicate the side on
which the elevation marker should be placed.

Curtain wall views use the same `W##` marking sequence as windows.

➡️ [**Generating Opening Views**](generating-opening-views.md)

------------------------------------------------------------------------

## Conform Existing Views

Use **Conform Views** to repair or reapply the expected opening-view
standards.

Depending on the view, Flow can restore items such as:

-   view template
-   scale
-   crop region
-   phase settings
-   view name
-   opening tag
-   opening metadata

➡️ [**Conforming Opening Views**](conforming-opening-views.md)

------------------------------------------------------------------------

## Dimension Window Views

Use **Dimension Window Views** to regenerate the standard dimensions on
window elevations.

The dimensioning workflow is intended for component Window family
instances. Curtain wall views are recognised and skipped rather than
treated as failed window views.

➡️ [**Dimensioning Window Views**](dimensioning-window-views.md)

------------------------------------------------------------------------

## Place Views on Sheets

Use **Place Opening Views on Sheet** to arrange generated opening views
onto the appropriate schedule sheets.

Window and door views use different placement workflows.

➡️ [**Placing Opening Views on Sheets**](placing-views-on-sheets.md)

------------------------------------------------------------------------

## Existing and Demolished Openings

The standard Generate Opening Views workflow creates window and door
views for **New** openings.

Existing and Demolished openings are not generated by the normal
window/door generation workflow.

------------------------------------------------------------------------

## Opening View Status in the Register

The Openings Manager audit checks the opening documentation and can
identify whether expected opening views are available and whether view
names remain consistent with the opening information.

Use **Refresh** after significant view changes to update the register.
