# Generating Opening Views

Use **Generate Opening Views** to create the standard elevation views
for New windows and doors.

Curtain walls use a separate interactive generation workflow.

------------------------------------------------------------------------

## Before You Start

Before generating views:

1.  Review the openings in Openings Manager.
2.  Resolve non-standard marks.
3.  Confirm that the required openings are included in the intended
    scope.

Opening marks should normally be standardised before view generation.

------------------------------------------------------------------------

## Choose the Scope

When Generate Opening Views is run from Openings Manager, choose the
required opening scope.

Depending on the current register state, this can include checked,
filtered or all openings.

Flow then checks the selected scope before creating views.

------------------------------------------------------------------------

## Non-standard Openings

If the selected scope contains non-standard openings, Flow does not
immediately generate the views.

Instead, it reports how many non-standard openings were found and
offers:

-   **Standardise Now**
-   **Cancel**

Choose **Standardise Now** to correct the openings before continuing
with the documentation workflow.

➡️ [**Standardising Openings**](standardising-openings.md)

------------------------------------------------------------------------

## Window Views

Flow generates window elevations for **New windows** in the selected
scope.

The window's **Mark** is used as the elevation view name.

For example:

``` text
W01
W02
W03
```

Flow also attempts to add the standard window schedule tag to the
generated elevation.

Existing and Demolished windows are not generated by this workflow.

------------------------------------------------------------------------

## Door Views

Flow generates door elevations for **New doors**.

Door views are type-based rather than instance-based.

This means that multiple door instances using the same door type produce
a single documentation view for that type.

The view name is based on the door type's **Type Mark** followed by:

``` text
-D
```

For example:

``` text
01-D
02-D
```

Flow also attempts to add the standard door schedule tag to the
generated elevation.

------------------------------------------------------------------------

## Curtain Walls

Curtain walls are not generated through the normal window/door
generation process.

Use the dedicated **Generate Curtain Wall Views** workflow instead.

➡️ [**Generating Opening Views**](generating-opening-views.md)

------------------------------------------------------------------------

## After Generating Views

After generation:

1.  Review the created opening elevations.
2.  Use **Conform Views** if existing views need to be repaired or
    brought back to the Flow standard.
3.  Dimension the window views.
4.  Place the opening views on the appropriate sheets.
5.  Refresh Openings Manager to update the view status.

------------------------------------------------------------------------

## If a View Already Exists

Do not create a second documentation view simply because an existing
view needs adjustment.

Use **Conform Views** to repair or restore an existing opening elevation
where appropriate.

➡️ [**Conforming Opening Views**](conforming-opening-views.md)
